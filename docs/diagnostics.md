## 4Kについて

HDR要求で3840×2160のmanifest候補やライセンス処理の進行は観測しましたが、4Kの実フレーム進行は確認できていません。記録したHDR masterの通常4K候補はPQで、SDR 4K候補はありませんでした。これは全作品・全アカウントの配信仕様を示すものではありません。

ハードウェアPlayReady / 4K HDRの実験でPCフリーズ・BSODが複数回発生しました。GPU・ドライバー・Windows・保護出力経路などの関与は未確定です。「AMD全体で再生不可能」「NVIDIAなら成功」「8 bpcなら安全」とは結論していません。

外部の類似報告と修正履歴は[関連報告・修正情報](related-issues.md)に分離しています。原典で確認できた範囲と、共有された二次情報を区別しており、本節の実機観測を外部チケットの再現・修正確認として扱いません。

## 診断表示の読み方

1. **manifest候補**: サーバーから列挙された宣言。選択・復号・表示の証拠ではありません。I-frame専用候補と通常候補も区別します。
2. **EME API受付 / keys-usable**: 能力照会や鍵状態。映像が動いたという意味ではありません。
3. **接続CDM**: 動画に付いたMediaKeysから追跡した状態。GPUドライバーの正しさまで証明しません。
4. **寸法 + 時間 + フレーム進行**: 短時間の実再生を判断する材料。5秒の4K判定が仮に成立しても、作品全編の安定性を保証しません。
5. **予定停止とエラー**: `time-limit-75s`などのガード停止と、復号・ライセンス・サイト側のエラーを分けて記録します。

## v0.3.16の境界

- 1080p単一候補の75秒比較、SDR候補だけのmanifest診断、SDK/EMEの各種比較を含みます。
- 4K HDR単一候補モードはSDK開始から30秒、または追加のnative鍵要求の前で停止する設計です。**初回のCDM処理でOSが停止する危険は残ります**。
- SDK連携は調査対象の `26.10.0-jasmine` に限定されています。未知の版・構造や必要なガードが成立しない場合、該当する比較を中止します。
- 公開のための変更は名前・MITメタデータ・配布構成・文書・テスト実行環境です。オリジナルv0.3.16の再生アルゴリズム、モード、タイマーは変更していません。
